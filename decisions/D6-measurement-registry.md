# D6: 測定レジストリ(R6)— 標準語彙カタログと現場レジストリ

Status: 確定 (2026-07-02。Fable精密レビュー6レンズ=blocker 2件/major 7件/minor 5件を全て反映・ユーザー承認済み)
用語は [../terminology.md](../terminology.md)、責務は [../responsibility-ledger.md](../responsibility-ledger.md) に従う。
D3課題キュー4への回答。Wave 0最後の設計ブロッカー。

## 決定1: 二層構造(正本の二義性の解消)

| 層 | 実体 | 内容 | 役割 |
|---|---|---|---|
| **標準語彙カタログ** | リポジトリ資産(版管理データファイル。Rustクレートとしてゲートウェイのバイナリに同梱) | measurement_keyの命名・正準単位・値型・意味論クラス・物理限界値域・チャネル役割 | 契約仕様書の一部として公開。「temperature_c を送ればどのIoTKitでも通じる」の保証=柱2の実体 |
| **現場レジストリ** | ゲートウェイDB(正本=D2 §1) | カタログから有効化した部分集合のコピー+現場カスタム定義+エイリアス表 | 受理判定(R8)の唯一の参照先 |

- **受理判定(R8)は常に現場レジストリのみを見る**。カタログへのネットワーク参照は存在しない(柱1)。
- 精密化: **診断・候補提示**(D1の「近い候補の提示」、R12のdry_run/validate)は同梱カタログを読んでよい
  (ローカル資産なので柱1無違反)。受理の可否判定だけがレジストリ限定。
- 業界比較: OPC UA companion spec(大域語彙)+EdgeX device profile(ローカル施行)の合成。既知の失敗
  (Sparkplug Bの単位規約なし、Home Assistantの単位文字列揺れ)は決定8で回避。

## 決定2: measurement_key文法(取り込み契約v1の安定意図リストに追加)

- 文字集合: セグメント=`[a-z][a-z0-9_]*`、名前空間区切りは**ドット `.`**。長さ上限64。
- **コロン禁止**(レビューblocker 1)。series_key文法 `<subject_id>:<measurement_key>:<channel>:<variant>`(D5)の
  区切り子を保護する。公開契約面の全消費者の `split(':')` を壊さない。
- 名前空間: 接頭辞なし=標準カタログ語彙 / `custom.`=現場定義。
- **キーとエイリアスは単一名前空間**として一意制約(ワイヤ上の申告キー空間の衝突防止)。

## 決定3: エイリアス機構(一級市民)

D1(DX節の後付けマッピング)・D5(リネームのエイリアス吸収、legacy_sensor_type互換別名)が既に依存している
機構を、レジストリスキーマに一級で定義する。

- エイリアス表: `alias → measurement_key`。**多:1を許容**(例: legacy 261と297→temperature_c)。
- 種別: `rename`(カタログ改名吸収=D5)/ `legacy_sensor_type` / `site_mapping`(現場の別名)。
- **1:多はエイリアスでは表現しない**: レガシー262(加速度+スペクトログラムの2ストリーム)の分解は
  アダプタランタイムのmeasurement写像(R3②)の仕事。エイリアスは受理時のキー解決のみ。
- 衝突検査: カタログエントリ有効化時に現場エイリアスと衝突検査。衝突時は自動有効化をブロックし
  明示解決(R14)を要求。将来カタログが `temp` を追加しても既存エイリアス `temp→custom.tank_level` を
  黙って上書きしない。

## 決定4: copy-on-enable+収束機構

**凍結**(レビュー追補案の骨子):
- カタログはソフトウェア更新と共に届く(バイナリ同梱。ランタイムのカタログ参照なし=ロールバック安全)。
- 「有効化」=カタログエントリを現場レジストリへ**コピーして固定**。エントリ単位の
  `catalog_version` スタンプ+**エントリrevision(内容ハッシュ)**を付与(版全体スタンプだけだと
  カタログが上がるたび全エントリが「古い」と誤検出されAIへのノイズになる)。
- 自動有効化: 認証済み送信者の能力宣言または初観測で、**カタログ内キーは自動有効化+R13監査イベント必須**。
  カタログ外キーは有効化せず検疫(決定6)。宣言更新で現れた新語彙も同じ扱い。

**収束**(レビューmajor: 凍結の対。レガシー実証例=測距センサー値域: コード2000mm vs 仕様1300mm):
- カタログ変更に**変更クラス**をデータ形式レベルで付与: `additive`(語彙追加)/ `corrective`
  (互換修正: 値域・説明の訂正)/ `breaking`(意味論破壊)。
- **ドリフトレポート**: 「同梱カタログ vs 有効化済みエントリ」の差分をR12で構造化常時公開+R13イベント発行。
  AIオペレーターの判断材料(柱3)。
- `corrective` はポリシー設定で自動適用可(**既定は提案のみ**)。`breaking` は決定5の新キー経路のみ。
- ロールバック(R21)で同梱カタログが巻き戻った場合、`entry_newer_than_bundle` は**正常・情報のみ**に分類
  (copy-on-enableにより動作は壊れない——この設計の実質的長所)。

## 決定5: 定義変更の2クラス(レビューblocker 2)

- **互換変更**(説明文・表示名・値域の緩和・エイリアス追加・チャネル役割ラベル): R14操作(dry-run付き)で可。
  値域の**狭化**も互換扱い(過去データの解釈は変えない。以後の検疫増加をdry-runで件数提示)。
- **意味論破壊**(単位・値型・意味論クラスの変更): 既存seriesを保有するエントリでは**構造的に禁止**。
  R14にこの操作は存在しない。唯一の経路=**新measurement_key発行+旧エントリdeprecated+superseded_by参照**
  (D5墓標原則の再利用)。
- 根拠: 「mV→V修正」は保存済み数値を不変のまま1000倍の解釈誤りとして全下流に波及させる。dry-runは誤操作を
  防げても意味論汚染は防げない。D5の背骨「意味が変わったら継続ではなく後継リンク付き断絶」と一貫させる。

## 決定6: 受理判定の判別表(R8×レジストリ状態)

| 入力の状態 | ack | 備考 |
|---|---|---|
| 既知キー・値域内 | `accepted`(disposition: durable\|staged) | D1既定 |
| 既知キー・値域外 | `accepted`+検疫 | D1既定(保存・可視化はする) |
| 未知キー(文法適合) | `accepted`+**disposition: `quarantined`** | 検疫として保存、series自動実体化(D5)。送信者はdispositionで未登録を知れる(fire-and-forget派も再接続時に分かる) |
| 宣言外channel_index | `accepted`+検疫 | 解釈可能なので破棄しない。宣言不一致イベント(D4のdeclaration_version検知に合流) |
| 値型不一致(構造的に解釈不能) | `rejected`+reason_code `value_type_mismatch` | 終端 |
| 文法違反キー | `rejected`+reason_code `malformed_measurement_key` | 終端 |

- **D1への波及**: ack dispositionを `durable | staged | quarantined` の3値に拡張。reason_code 2種を追加。
  measurement_key文法を安定意図リストへ追加。

## 決定7: 値域の3層入れ子

| 層 | 意味 | 制約 |
|---|---|---|
| カタログ | 物理限界(センサー仕様由来) | 外殻。現場で狭化はできるが拡げられない |
| レジストリエントリ | 現場既定 | 外殻内 |
| series個別(D5 series単位メタデータ) | 個別上書き(炉の熱電対と冷凍庫の熱電対) | 外殻内 |

- R8の検証は **series層→レジストリエントリ→カタログ物理限界** のフォールバック。
- **単位は全層で不変**(層をまたぐ単位上書きは存在しない)。

## 決定8: 単位の正準規約

- **1 measurement_key = 1正準単位**。単位変換はドライバのデコード段(R3①、データシートの数学)の仕事。
  レジストリに単位上書き機構は置かない(レガシーの「キーに単位を焼き込む」方式の良い性質を継承)。
- 単位フィールドは **UCUMコード+表示用文字列** の2欄(例: `Cel` / `℃`)。

## 決定9: custom定義の作成主体と輸出入

- **デバイス/アダプタはcustom定義を作成できない**。未知キーは検疫→人間/AI(R14)が
  「カタログキーへのエイリアス」または「custom新設」で解決する。ベンダーAとBの `custom.temp` が
  異なる単位で無音衝突する事故を構造的に防ぐ。翻訳責任は送る側(柱2)と整合。
- custom定義の**エクスポート/インポート**をR14操作として定義(dry-runで衝突差分提示)。
  複数ゲートウェイ現場・複数現場間の語彙ドリフト(同綴り異義)への対処経路。
  形式は契約v1で定義、実装はWave 1。※R22スナップショットは箱交換用であり別物。
- **R9派生値のキーは `custom.` が正面玄関**(逃げ道ではない): 4-20mA→タンク水位のような
  スケーリング後工学値は本質的に現場固有。初日から必須の経路として明記する。

## 決定10: 値型体系v1(構造化値型を含む — 先送り不能)

- `scalar`: float / int / bool
- `array<scalar, N>`: 固定長配列(1観測が本質的にベクトルの場合)
- `record`: 名前付きフィールドの構造化レコード(フィールド=scalarまたは固定長配列。ネストなし)
- 多軸測定(加速度x/y/z)は**チャネルで表現**し(決定11)、配列型は使わない——チャネル単位の
  検疫・較正・series分離(D5)がそのまま効くため。
- **vibration_spectrum は record として契約v1で予約**(レガシー262のスペクトログラム=11フィールドを
  表現可能なことを確認済み)。実装(保存・配送)は第二波のまま——「振動は契約だけ予約」という
  プロダクト判断(台帳)は、値型体系が最初から表現能力を持つことで初めて空語でなくなる。

## 決定11: 初期語彙(契約定義v1)とレガシー統合対応表

方針: **キーはプロバイダ中立**(`_jig` 等の接尾辞焼き込み禁止=用語集プロバイダ原則)。プロバイダ差・
電気的界面差(ドライ/ウェット)はhardware_id・台帳・能力宣言側の情報であり測定意味論ではない。

**位置づけの明確化**: 本表のmeasurement_key列は普遍的な物理量の語彙であり標準カタログの資産。
**legacy_sensor_typeエイリアス列は標準カタログの一部ではなく移行シム**——レガシー移行(D2 Phase 3.5)で
該当現場の現場レジストリにのみ播種される。コアの語彙にsensor_type番号は現れない。
BravePI/BraveJIGはプラットフォームの最初の乗客(Wave 0テストケース)であって、依存先ではない。

| measurement_key | 正準単位(UCUM) | 値型 | 意味論クラス | チャネル役割 | legacy_sensor_typeエイリアス |
|---|---|---|---|---|---|
| `contact_state` | 1(無次元 0/1) | bool | sensor | 汎用(デバイス側ラベル) | 257(PI接点入力)、294(JIGドライ)、295(JIGウェット) |
| `contact_output_state` | 1 | bool | **actuator_state** | 汎用 | 258(PI接点出力)、296(JIG接点出力) |
| `voltage_mv` | mV | float | sensor | 汎用(CH1/CH2) | 259(PI ADC)、299(JIG ADC) |
| `distance_mm` | mm | float | sensor | 単ch | 260(測距) |
| `temperature_c` | Cel | float | sensor | 単ch | 261(PI熱電対)、297(JIG熱電対) |
| `acceleration_mg` | m[G](mG) | float | sensor | **固定: 0=x, 1=y, 2=z** | 262(加速度ストリーム側) |
| `differential_pressure_pa` | Pa | float | sensor | 単ch | 263(差圧) |
| `illuminance_lux` | lx | float | sensor | 単ch | 264(照度) |
| `current_ma` | mA | float | sensor(搬送信号) | 汎用(CH1/CH2) | 298(JIG 4-20mA) |
| `vibration_spectrum` | (複合) | record(**契約予約・実装第二波**) | sensor | 単ch | 262(スペクトログラム側) |

補足:
- **262は1:多**: レガシー1ストリーム→ `acceleration_mg` + `vibration_spectrum` の2キー。分解は
  アダプタランタイムの写像で行う(エイリアスではない=決定3)。
- **298は搬送符号**: 生値series(`current_ma`)+R9スケーリングによる工学値series(`custom.tank_level` 等)の
  2段構成を標準形とする(決定9)。
- 接点系のカウント/パルス集計はmeasurement_keyを増やさず **series_variant**(count / pulse_count、D5)で表現。
- 移行seriesは `value_semantics: raw_legacy`(D5レガシー移行)。
- JIG系(294-299)のアダプタ実装はWave 0対象外(ADR 0007)だが、語彙とエイリアスは契約定義v1に含める
  (D3読み替え規則)。
- 意味論クラス: `sensor` / `actuator_state`(接点出力=アクチュエータの状態報告)。以後の追加はカタログの
  additive変更。

## 決定12: チャネル役割の2態

カタログエントリは任意の正準チャネル役割(index→役割名)を持てる:
- **固定型**: 多軸測定はカタログが役割を固定(acceleration_mg: 0=x/1=y/2=z)。出口契約の消費者が
  台帳参照なしにチャネルを解釈できる。
- **汎用型**: 物理チャネル(ADC CH1/CH2)はデバイス側ラベル(能力宣言・台帳)に委譲。
