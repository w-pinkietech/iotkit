# Issue #98: 初回登録導線の操作レビュー

## 目的

未設定の収集ノードが MQTT で検出されてから、管理者が Console 上で登録し、
機器・センサー・計測ルールを設定するまでの初回導入導線を確認した。

このレビューは、開発者がクリーンなテスト環境で行った内部レビューである。
非 IT 担当者によるユーザビリティ確認を扱う
[#91](https://github.com/w-pinkietech/iotkit-next/issues/91) の代わりにはならない。

## 条件

- 実施日: 2026-07-24
- 操作者: 初見の現場管理者を想定した `owner`（システム管理者）
- ブラウザ操作: Playwright MCP
- ビューポート:
  - 1440 x 1000
  - 1024 x 800
- 開始地点: `/status`
- データ: 既存 DB・設定・認証情報を流用しない初回導入 fixture
- 通信: MQTT を通した収集ノード descriptor、登録要求・結果、raw record、ACK

## シナリオ

1. Console にログインする。
2. `/status` から未登録の収集ノードを見つける。
3. 収集ノードを登録し、自動確認で登録完了を待つ。
4. 表示された次の操作から、最初の機器を設定する。
5. センサーを「温度（方式未確認）」、小数 1 桁、単位 `°C` として設定する。
6. 通常の測定値ルールを追加する。
7. `/status` に戻り、現在値と設定完了状態を確認する。

直接 URL を組み立てず、画面に表示された導線だけで操作した。
登録と設定フォームでは、可能な範囲でキーボード操作も確認した。

## 初回レビューで見つかったこと

| 重要度 | 観察 |
| --- | --- |
| High | 登録処理中の画面が自動更新されず、完了を知る方法が分かりにくかった。 |
| High | raw データは受信中なのに、プレビューが「更新を確認できません」と表示して状態が矛盾した。 |
| Medium | `Cel`、Unix ミリ秒、ledger epoch など、実装上の表現が利用者向け画面に露出した。 |
| Medium | 方式を特定できない温度センサーを選べなかった。 |
| Medium | 保存結果が見えず、ルール保存後に別の設定タブへ戻った。 |
| Medium | プレビューの `42.5` と状態画面の `42` で小数表示が一致しなかった。 |
| Medium | 初回設定完了後に、次に何を確認すべきか表示されなかった。 |

## 改善内容

- 登録処理中は 3 秒間隔で状態を自動確認し、上限到達時は停止を明示して
  「今すぐ確認」を表示するようにした。
- 登録完了後も自動遷移せず、管理者には
  「次へ: 機器を設定」を 1 件だけ主要操作として表示するようにした。
- 閲覧者には編集リンクを出さず、設定管理者への依頼が必要だと表示するようにした。
- ルール未設定でも、保存を伴わない一時設定で raw データをプレビューできるようにした。
- 保存結果を通知し、ルール保存後は計測ルールのタブを維持するようにした。
- タブ切替時は URL の `tab` を履歴追加や再読込なしで同期し、重複を除くようにした。
- `Cel` を `°C`、時刻をローカル日時、ledger epoch を
  「データ系列の世代 ID」として利用者向けに説明した。
- 「温度（方式未確認）」を追加し、保存後の見出しや状態画面にも同じ表記を使うようにした。
- プレビューと状態画面で同じ小数桁設定を使うようにした。
- 未設定の設置場所は入力欄を空にし、特定の現場概念に依存しない
  `例：乾燥炉入口` をプレースホルダーにした。
- 「測定値」はセンサー値をそのまま記録・出力する選択だとフォーム内で説明した。

## 再レビュー結果

1440 x 1000 と 1024 x 800 の両方で、登録から計測ルール作成、状態確認まで
画面上の導線だけで完了した。

- 登録完了ページに留まり、完了通知と 1 件の次操作が表示された。
- 未設定の設置場所は空で、プレースホルダーは `例：乾燥炉入口` だった。
- 「温度（方式未確認）」と `42.5 °C` が設定画面と状態画面で一致した。
- 連続した保存後も `saved`、`result`、`tab`、`error` が URL 内で重複しなかった。
- 計測ルールと基本設定の切替直後に URL が表示中のタブへ同期した。
- タブ切替でページ再読込やブラウザ履歴の追加は発生しなかった。
- 1024 px 幅で横方向のはみ出しや操作不能な箇所はなかった。
- ブラウザコンソールはエラー 0 件、警告 0 件だった。

## 未解決事項

- この内部レビューでは、実際の非 IT 現場担当者が用語や導線を理解できるかまでは
  証明できない。実利用者からの観察は #91 で継続する。
- 実機交換、長時間の MQTT 切断、保存容量上限などの運用耐性は、このシナリオの対象外。
