# Site Console センサー一覧・詳細設計

## 目的

現場担当者がセンサーを探し、現在値を確認し、必要な権限があれば同じセンサーの設定まで迷わず進める導線を作る。

現在の `/monitor`（現在値）・機器詳細（基本情報）・`/signals`（値の変換）という画面分割は、同じセンサーを複数画面で探し直す必要がある。v1ではセンサー一覧とセンサー詳細へ集約する。

## 画面構成

### センサー一覧

- 正規URLは `/sensors` とする。
- サイドメニューの表示名は「センサー一覧」とする。
- 一覧には次を表示する。
  - センサー名
  - センサーの種類
  - 現在値と表示単位
  - 受信状態
  - 最終受信
  - 所属Edge
  - 所属デバイス
- 検索と受信状態による絞り込みを維持する。
- 一覧行全体を選択可能にし、`/sensors/{signal_ref}` へ遷移する。
- 一覧画面には設定フォームを置かない。
- 開発用の操作確認では、熱電対・照度・接点入力を別々のセンサー例として用意し、
  数値、しきい値を持つ数値、ON/OFFの各設定体験を確認できるようにする。

### センサー詳細

ページ見出しを「センサー設定」とし、対象センサー名を説明文とパンくずで示した直後に、
設定と結果を同時に見られる作業領域を表示する。

1. パンくず直下に「受信した値 → Siteで作る値 → 外部へ送る」のコンパクトな3段経路
2. 左上に、センサー名・種類・値の見せ方・表示単位と、全ルールで共有する入力補正
3. 左下に「正常値」と「異常検知」のルールカード一覧、および選択中の一つのルール設定
4. 右列に現在値・受信状態・最終受信と、受信値、共通補正値、選択中ルールの結果を重ねた設定シミュレーション
5. 左列の末尾に、所属Edge、所属デバイス、Edgeから届いたデータ種類・値形式・単位・チャンネルを
   折りたたんで表示

3段経路の入力欄はInput Adapter名を推測せず、Edge、デバイス、Edgeから届いた生値とcanonical unit、
最終受信を表示する。Site欄はsemantic rule名とgeneric kindを最大2件まで表示し、残りは件数で示す。
外部出力欄は使用中・停止中のroute件数、変換エラー件数、MQTT配送中件数を集約表示する。ruleとrouteの対応は各rule
カードでOutput Adapter、非秘密の送信先識別、変換状態、配送状態を並べる。既存routeはviewerも閲覧でき、
routeがないruleにはadmin以上だけ「外部出力を追加」を表示する。

一つのセンサーへ複数ルールを追加できる。「正常値」には補正値、ON/OFF、累積値を、「異常検知」には
alarmを表示する。この区分は画面上の整理だけであり、正常/異常をDBの別entityや優先順位にはしない。
各カードにはルール名、結果種類、現在結果、設定状態を一行で示す。選択した一枚だけを編集領域へ展開し、
同時に複数の長いformを並べない。

「センサーの種類」は物理的な種類を表し、「測定値」と分ける。たとえば熱電対の測定値は温度であり、
`temperature_c`はEdgeから届く測定キーである。選択肢は「熱電対」「照度」「接点入力」と表示し、
旧データの`temperature`は互換読込時だけ「熱電対」へ読み替える。

所属デバイスが存在する場合は機器管理のデバイス詳細へリンクする。

デスクトップでは大きな概要カードや手順カードを挟まず、設定開始から保存、現在値、グラフ、試算結果までを
同じ画面内に収める。少なくとも1440×1000の表示領域では、通常の数値設定を縦スクロールなしで完了できること。
接続元のような確認頻度の低い情報を開いた場合と、条件によって追加項目が現れる場合だけ、必要なスクロールを許容する。
狭い画面では設定、実信号プレビューの順に一列で表示する。

### 設定シミュレーション

設定フォームだけを見ても、受信値に対して補正・しきい値・累積・alarm等の各ルールがどう働くか
判断しにくい。そこで、設定欄の隣に受信値と設定結果を重ねたグラフを置き、保存前の入力補正と
選択中ルールの変更を即座に試せるようにする。

- 受信開始以降の利用可能なデータを使い、最大1時間分を表示する。
- 1時間以内に20,000件を超える場合は、新しい20,000件を入力上限とする。
- ブラウザへ返す描画点は最大300点とし、実際の期間、入力件数、要約後の点数を表示する。
- 数値は区間ごとの先頭・最小・最大・末尾を考慮し、短いピークを消さない。
- 累積値、ON/OFF、アラームはルールごとに入力を受信順にすべて評価してから描画用に要約する。300点を超える場合も、
  区間内の変化回数、ONの割合、累積増分を合算し、結果を失わない。
- 数値では受信値を灰色、共通補正後を青緑、選択中ルールのしきい値を橙色で表示する。
- ON/OFFとアラームではしきい値と有効区間、累積値では増分と累積結果を表示する。
- 累積値の先頭入力はbaselineとして加算せず、累積結果は「表示範囲内の試算」であることを明示する。
- データが1件なら点として表示する。0件なら空のグラフと「試す値」を表示し、履歴を捏造しない。
- 「試す値」は履歴の有無にかかわらず使え、共通補正後の値と全ルールの状態判定結果を表示する。
- 新しい実信号を受信した場合は、グラフだけでなく現在値と最終受信表示も自動更新する。
- 過去データを使うのは保存前の試算だけであり、設定保存後に過去の意味付けや外部出力を作り直さない。

共通入力補正はscaleとoffsetだけを持ち、表示単位・表示桁数とは分ける。すべてのルールが同じ補正後値を
入力にするため、ルールごとに補正値を重複入力させない。

ルール追加時は「作る値」を次から選ぶ。曖昧な「用途」というlabelは使わない。

- 補正後の数値: 共通補正後の値をsemantic observationにする。
- ON/OFF状態: High側・Low側のどちらをONとするかを設定する。
- 回数の累積: どちら側を数える状態とするかと数え方を設定する。
- 異常の有無: どちら側を異常とするかを設定する。

各ルールは必須の自由入力名を持つ。例えば同じ接点入力へ「稼働状態」「生産回数」「停止アラーム」を
設定できる。作成後に「作る値」は変更できず、変更したい場合は既存ルールを終了して新しいルールを作る。
一つのセンサーで有効にできるルールは最大16個とする。

- アナログ入力では立ち上がりと立ち下がりのしきい値を別々に入力する。
- 接点入力ではしきい値を表示せず、High/Lowと立ち上がり・立ち下がりの確定待ち時間を入力する。
- 立ち上がり・立ち下がりには、それぞれ0〜300秒の確定待ち時間を設定できる。
- 累積値は管理者がルール単位で0へ戻せる。リセット要求を受理した時点までの未処理入力を数え終えてから
  0にし、値0の結果を明示的に一件作る。リセットはrule revision変更と分けて監査記録へ残す。
- 選択した「作る値」と関係のない条件や数え方は非表示かつ送信対象外にする。
- 「単位なし」を選んだ場合は、以前入力された表示単位を消して送信対象外にする。

しきい値の順序は常に「立ち下がり ≤ 立ち上がり」とする。この間は直前の確定状態を維持する。
High側有効では立ち上がりで有効、立ち下がりで無効となり、Low側有効ではその逆となる。
確定待ち時間中に条件から外れた場合はその候補を取り消す。

設定フォームの入力は約300ms待ってから再計算し、自動更新は最大1秒に1回とする。再計算はMQTTの受信・保存経路から
分離し、グラフ表示の遅延や失敗がデータ収集を止めないようにする。

### シミュレーションAPI

設定シミュレーションはSite Console API設計のsemantic configuration previewを使う。保存済み設定の
グラフは閲覧者も参照できるが、
保存前の設定案を送って試せるのは設定管理者とシステム管理者だけとする。不正な設定は項目単位のエラーとして表示し、
最後に成功したグラフを残す。シミュレーションが失敗しても設定フォームとデータ受信は利用可能なままとする。

保存は共通入力補正と各ルールで独立させる。一つのルールのvalidation errorで別ルールの保存済み設定や
runtimeを変更しない。入力補正を変更した場合は全ルールへfuture-onlyで影響することを確認画面に明示する。
ルール追加・更新・終了はstableなルールIDを対象にし、外部出力の紐付けをrevision変更で失わない。

## 権限

- 閲覧者は一覧と詳細の全情報を閲覧できる。
- 閲覧者には設定フォームと識別用の内部参照を表示しない。
- 設定管理者とシステム管理者は、詳細画面で基本情報と値の変換を変更できる。
- 既存のサーバー側権限検査を維持し、画面上の非表示だけに依存しない。

## 既存URLとの互換性

- `/monitor` は `/sensors` へリダイレクトする。
- `/signals` は `/sensors` へリダイレクトする。
- 既存のPOST/API URLは維持する。
- 詳細画面から保存した場合は、同じ `/sensors/{signal_ref}` に戻す。
- 機器管理や概要にあるセンサー導線は、新しい一覧または詳細へ変更する。

## エラーと不完全な情報

- 存在しない `signal_ref` は404とする。
- プロファイル未設定でも、Edgeから届いた候補と現在値を表示する。
- 所属デバイスが解決できなくても、センサー詳細自体は表示し、判明しているEdge情報を残す。
- 値の変換が未設定の場合は「未設定」とし、設定可能な権限には次の操作を明示する。

## テスト

- 一覧がセンサーの現在値と所属情報を表示する。
- 一覧行が正しい詳細URLへリンクする。
- 詳細が現在値・基本情報・共通入力補正・複数ルールを表示する。
- データが0件、1件、通常件数の場合に設定シミュレーションを表示する。
- 1時間と20,000件の入力上限、および300点の描画上限を守る。
- 数値の短いピークと、ON/OFF・アラーム・累積値の区間集計を要約後も保持する。
- 保存前の共通補正・複数ルールのしきい値・累積設定と「試す値」を製品と同じ変換で評価する。
- 同じ信号でON/OFF、累積値、alarmを同時に設定・試算・保存できる。
- あるルールのvalidationまたはprojection失敗が他ルールの設定と結果を止めない。
- 立ち上がりと立ち下がりで異なるしきい値・確定待ち時間を製品と同じ変換で評価する。
- 確定待ち時間中の再起動後も同じ状態遷移になる。
- 累積値リセットがsemantic ruleを改訂せず、受理境界以前の値を数え終え、監査記録と値0の結果を残す。
- シミュレーションがrawデータ、設定、監査記録、外部出力を変更しない。
- 閲覧者に変更フォームを表示しない。
- 閲覧者は保存済み設定だけを表示でき、設定案の試算は拒否される。
- 設定管理者が保存後に同じ詳細画面へ戻る。
- 未知の `signal_ref` が404になる。
- 旧URLが新しい一覧へリダイレクトされる。
- PC幅とスマートフォン幅で一覧・詳細を実画面確認する。

## 対象外

- 長期履歴の閲覧・分析
- 複数センサーの一括編集
- センサーごとの権限設定
- センサー詳細からのデバイス・Edge登録
